# CHALLENGE PLACE — интеграция с сайтом турнира

Источник требований: твой текст о боте («бот загружает данные с Challenge Place по
ссылке и туру, сам определяет долги, сохраняет в базе, публикует пост»).
Сайт = внешний источник правды по сыгранным матчам. Доступ и структура сайта —
уточняются (нужна ссылка на страницу турнира: проверим, что отдаётся без логина,
есть ли JSON под капотом — часто у таких сайтов защита слабая и всё парсится).

## Что сканируем (автоскан)
1. **Календарь тура** — пары матчей, дедлайны → создаём/обновляем `matches`
   (клубы, тур, дедлайн) на старте тура.
2. **Таблицу дивизиона** — очки, И/В/Н/П, мячи → сверяем с нашей таблицей
   (расхождение = сигнал «результат не внесён у нас»).
3. **Результаты сыгранных матчей** — счёты → импорт в `matches` со статусом
   `reported`, источник = challenge-place. Если матч есть и у нас (через OCR-скрины) —
   сверяем счёты; расхождение → алерт админу.

## Поток тура (полный цикл)
1. Админ кидает боту ссылку на тур Challenge Place → бот парсит календарь →
   создаёт матчи и дедлайны → анонс в чат дивизиона → мини-апп показывает линию.
2. Игроки играют в FC27 → присылают скрины боту → OCR → подтверждение → результат.
3. Периодический скан (или по команде `/scan`): таблица+результаты с сайта →
   сверка → авто-долги (не сыграл / не внес / счёты разошлись).
4. Пост «Долги по турам» в канал → напоминания 3×/день (08:00/12:00/18:00 МСК).
5. Конец тура: всё сошлось → тур закрывается, кэфы на следующий тур генерятся.

## Долги (`debts`)
- «не сыграл матч к дедлайну» → ТП 0:3 (walkover) + долг.
- «не внес результат» → если сайт знает счёт, а у нас нет — вносим с сайта + долг.
- «счёт разошёлся» → замораживаем матч до решения админа.

## Антифрод / надёжность
- Кэш страниц сайта + ETag, ретраи с бэкоффом (как у Дракобета на 429), лимит частоты.
- Если сайт упал/поменял вёрстку — бот не падает: скан в try/except, алерт админу.
- Всё, что импортировано с сайта, помечено источником — можно откатить.

## Рекон 24.09 — РЕЗУЛЬТАТ (реальный браузер, успешно)

**Главное: отдельного API у сайта НЕТ, и логин/куки НЕ нужны.**
SPA отдаёт весь контент турнира в `window.__INITIAL_STATE__` прямо в HTML (SSR):
same-origin XHR = только статика (index.js/css, логотипы), никаких /api-запросов.
Cloudflare пропускает настоящий браузер (IAB/Chrome — автоматически).

**Структура `__INITIAL_STATE__` (69 КБ):** `rooms["room-challenge-dashboard"]`:
- `competitors` — участники: id, name, acronym, img, stats {wins,draws,losses}
  (в тестовом турнире 31 сборная — «КЛАССИКА ТУРНИР СБОРНЫХ - KURILKA»)
- `latestMatches` / `upcomingMatches` / `liveMatches` — матчи: id, stageId,
  roundId, **seriesId** (серии!), order, date, homeCompetitor/awayCompetitor,
  **homeScore/awayScore**, winnerSlot, live
- `latestGrids` / `upcomingGrids` / `liveGrids` — сетки (у завершённого турнира пустые)
- `champions`, `players`, `timeSettings`, `config` (15 КБ настроек)

**Вывод для парсера (сессия 7):** headless-браузер (Playwright) в парсере:
открыть URL → дождаться загрузки → вытащить `__INITIAL_STATE__` из HTML
(regex по `<script>window.__INITIAL_STATE__=...`) → JSON.parse → сопоставить
competitors/матчи с нашими `matches`/`clubs`. cf_clearance HttpOnly — из
document.cookie не достаётся, поэтому curl-вариант с куки ненадёжен; честный
путь — только браузер. Логин нужен только для приватных кабинетов, дашборд
турнира полностью публичен.

**Иерархия матча на сайте: stage → round → series → матчи (order 1..n)** —
серии до 2 побед, как у нас в кубках (план 09). Прямое соответствие нашей модели.
