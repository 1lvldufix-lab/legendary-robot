# LOGOVO.BET — разбор мини-аппа (@logovabot, «ТЕМШИК»)

Дата съёма: 2026-09-24. Вход: через Telethon-сессию `acc2` (аккаунт @Verysecretqwenapi,
id 8061798118) — `RequestWebView` отдал честный `tgWebAppData`, подписанный Telegram.
Хост аппа: `https://floppy-gel-desktops-zshops.trycloudflare.com/app` (временный
Cloudflare-туннель — скоро умрёт, поэтому всё скачано локально).

## Стек (по коду)

- **Фронтенд**: чистый vanilla JS на ES-модулях, БЕЗ фреймворка и сборки.
  - `app.js` (66 КБ) — контроллер приложения, оркестрация событий
  - `ui.js` (128 КБ) — рендер всех экранов (UIRenderer, escapeHtml)
  - `store.js` (17 КБ) — клиентское состояние
  - `api.js` (15 КБ) — HTTP-клиент с кэшем
  - `admin.js` (84 КБ) — админ-панель (видна всем, но сервер режет по `is_admin`)
  - `tg.js` (3 КБ) — мост к Telegram.WebApp (достаёт initData)
  - `effects.js` (3 КБ) — частицы/эффекты
- **CSS**: 3 файла (`main.css`, `components.css` 113 КБ, `coupon.css`) + inline critical CSS
  в HTML. Тёмная тема, шрифты Inter + Outfit (Google Fonts), акцент — золото #f5b027.
- **Бэкенд**: Python (`api/server.py` — упомянут в комментариях HTML), отдаёт статику с
  версионированием `/v/<хэш>/...` и JSON API. Авторизация: заголовок
  **`X-Telegram-Init-Data`** = сырой initData из Telegram.WebApp.

## Структура приложения (нижняя навигация)

1. **Линия** — вкладки Кубок / Дивизион 1–5, поиск матчей, блок «Рекомендации для вас»,
   карточки матчей (П1/Х/П2 + «Статистика & H2H» + «Все рынки (15+)»), туры 7/8.
2. **Центр** — Матч-Центр & H2H выбранного матча: вкладки «Ставки и Рынки» /
   «Статистика & H2H» (история очных, ср. голы, ТБ2.5%) / «Инсайты»
   (Аналитика «Темшик»: П1 59% / X 25% / П2 16%, уверенность 53%, Elo 1511.9 vs 1450.5).
3. **Турнир** — таблица 16 клубов (И В Н П ЗГ ПГ Р-Г О).
4. **Купоны** — история прогнозов с фильтрами (Все/В игре/Выигрыши/Проигрыши/…).
5. **Мой Клуб** — личный кабинет клуба (открывается после назначения клуба админом
   через бота «Логово Фиферей»).
6. **Кабинет** — профиль (@username, звание, уровень), статистика каппера (ROI,
   проходимость, ср. кэф, лучший выигрыш), достижения 0/29 (сетка карточек с наградами
   в монетах и XP), кнопка «Зал Славы Лиги» (топ-20 по балансу).

Модалка «Все рынки (15+)»: исход матча, двойной шанс, тоталы (1.5/2.5/3.5),
обе забьют, инд. тоталы обеих команд, фора ±1.5 → кнопка «Открыть полную аналитику & H2H».

Купон: ординар/экспресс (экспресс залочен), сумма 10–50 000, макс. выплата 10 000,
макс. 6 открытых купонов, open exposure 20 000 (из `/api/bootstrap` → `bet_limits`).

## Защита (что можно/нельзя выкачать)

- GET-эндпоинты открываются с заголовком `X-Telegram-Init-Data` — без капчи/CSRF,
  initData не протухает (работает и на следующий день). Образцы сняты 24.09 дважды.
- Статика: фронт + `/assets/logos/*.png` — отдаются без авторизации.
- НЕТ доступа: бэкенд-код (server.py наружу не торчит), админские `/api/admin/*`
  (нужен is_admin), чужие приватные данные.
- **Стресс-тест ставки (24.09, с разрешения совладельца):** POST `/api/predictions`
  с подменённым кэфом (отправили 999 при реальном 1.85, матч 5874) → сервер
  ОТКЛОНИЛ: `ODDS_CHANGED` «Коэффициент изменился: 999.0 → 1.85». Баланс не тронут
  (677). **Сервер не доверяет клиентскому кэфу** — уязвимости подмены кэфов НЕТ.
  Есть rate-limit (`rate_limit_exceeded`). Урок для клона: сервер сверяет присланный
  odd со своим, при расхождении → ODDS_CHANGED, фронт показывает модалку
  пересогласования (`showOddsChangedModal` уже есть в портируемом фронте).
- **Аудит критичных багов (24.09, с разрешения совладельца) — всё чисто:**
  - Подделка авторизации («за другого юзера»): нет заголовка / мусор / битая
    подпись / без hash / пустой hash — все 5 → `401 unauthorized`. Обойти
    HMAC-валидацию initData и войти за чужой id НЕЛЬЗЯ (подпись на ключах Telegram).
  - IDOR: `GET /api/predictions/1` (чужая ставка) → `404`; `progression?user_id=1`
    параметр игнорирует. Скоупинг по юзеру из initData работает.
  - Double-spend: повтор POST с тем же `idempotency_key` → тот же `bet_id` (832),
    списание однократное (677→667). Дедуп корректный.
- **Общий вердикт защиты оригинала:** для самописного проекта — крепко. Критичных
  дыр (подмена кэфа, вход за другого, IDOR, двойное списание) не найдено.
- **Глубокий аудит (24.09, второй раунд) — найдено 2 неочевидные проблемы:**
  1. **initData не проверяется на свежесть** (средняя тяжесть). Наш initData,
     выданный утром, сервер принимал вечером (10+ часов) без вопросов. Данные
     initData зашиты в URL аппа — если юзер поделится ссылкой/скрином с URL,
     утечёт ПЕРМАНЕНТНЫЙ доступ к его аккаунту в аппе (баланс, ставки) без срока
     годности. Рекомендация оригиналу: отбрасывать auth_date старше ~24ч
     (рекомендация Telegram). Для клона: проверку свежести делаем сразу.
  2. **Слабая типизация входа** (низкая): `amount: "10"` (строка) сервер принял
     как ставку 10 🪙 (приведение типов). Не эксплуатируется напрямую, но
     показывает небрежный разбор входа — в клоне строгая валидация типов.
- **Проверка «а можно ли это обойти» (24.09, 3-й раунд):**
  - initData из query-параметра (без заголовка) → `401`: принимает только заголовок,
    поверхность утечки не шире URL/скринов.
  - Приведение типов: `"10.7"` → отказ («должна быть целым числом»), `"1e2"` → отказ
    («некорректная сумма»), `true` → приводится к 1 → отказ по min-bet. Дублированный
    ключ `amount` в JSON (10 и 100) → парсер взял последний (100), проверка и списание
    согласованы — путаницы «проверил одно, списал другое» НЕТ. Итог: подделать/обойти
    обе находки не удалось, они лабораторные.
- **Что подтверждено как защищённое во 2-м раунде:** админка режется на сервере
  (`/api/admin/panel/*` → 403 без is_admin); отрицательная сумма → min-bet отказ;
  99999999 → `MAX_BET_EXCEEDED`; экспресс с двумя одинаковыми ногами → отказ
  «Нельзя добавлять несколько исходов из одного матча» (дубли-кэф не проходит);
  SQL-подстановка в параметрах обрабатывается штатно.
