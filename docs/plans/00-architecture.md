# АРХИТЕКТУРА — клон системы «Логово» (турнир + мини-апп + ставки)

Дата: 2026-09-24. Референс: разбор оригинала в `../logovo-copy/` (фронтенд скачан целиком,
API-контракт восстановлен). Заимствования из елобота и Дракобета — в `02-reuse-base.md`.

## Состав системы (один Python-процесс на старте, модульно)

```
┌────────────────────────────────────────────────────────────┐
│  bot/main.py  (python-telegram-bot 21.7, long-polling)     │
│  ├── меню-бот турнира: клубы, результаты, трансферы,       │
│  │   долги, напоминания, бюджет-калькулятор                │
│  ├── job-планировщик: напоминания 3×/день, расчёт ставок,  │
│  │   переходы туров, бэкапы                                │
│  ├── мини-апп сервер: aiohttp на том же процессе           │
│  │   ├── /api/* — JSON API (контракт из logovo-copy)       │
│  │   └── /static — фронт (порт с оригинала + правки)       │
│  ├── OCR FC27: vision-провайдеры (из elobot ocr.py)        │
│  └── парсер Challenge Place (новый модуль)                 │
└──────────────┬─────────────────────────────────────────────┘
               │
        БД: SQLite ⇄ Postgres (db_backend.py из елобота, как есть)
```

Почему так: оба референса (elobot, drakobet) — python-telegram-bot 21.x, привычно и
работает; aiohttp уже в зависимостях Дракобета, поднимает API мини-аппа в том же
процессе без отдельного деплоя. Мини-апп — статика без сборки, как у оригинала.

## Авторизация мини-аппа

Клиент получает `initData` от Telegram.WebApp → шлёт в заголовке `X-Telegram-Init-Data`
(так же у оригинала). Сервер проверяет подпись HMAC по официальной схеме Telegram
(валидатор в `miniapp/server.py`). Без валидной подписи — 401. Админские эндпоинты
проверяют `users.is_admin`.

## Схема БД (объединение: елобот 24 таблицы + Дракобет + новое для мини-аппа)

Ядро турнира (из елобота, сохраняем имена):
- `players` — игроки: username, telegram_id, game_nickname, elo, голы/ассисты, W/D/L, баны
- `tournaments` — турнир/сезон: тип, стадия, туры (tours_enabled/current_tour), настройки
- `tournament_players` — состав: клуб, дивизион, групповые очки (переименуем поля под лигу)
- `matches` — матчи: счёт, голы JSON, стадия, тур, статус pending/reported/confirmed, дедлайн
- `match_goals` — события голов (для бомбардиров)
- `tournament_elo` — изолированный Elo на турнир
- `tournament_admins`, `tournament_audit_log`, `processed_screenshots`, `reminder_log`

Новый слой «Лига клубов» (под мини-апп, этого нет в елоботе):
- `clubs` — клуб: название, эмблема, дивизион_id, владелец(игрок), бюджет, стадион-имя
- `divisions` — 1..5 (+ `group_chat_id`), привязка к турниру/сезону
- `tours` — туры сезона: номер, статус (open/locked/played), дедлайн
- `transfers` — трансферы: клуб_от, клуб_в, игрок, статус (pending/approved/rejected), сумма
- `debts` — долги: клуб, сумма, причина (тур/трансфер), статус, источник-парс
- `challenge_links` — ссылки Challenge Place по туру для парсера

Ставки мини-аппа (гибрид Дракобета и контракта оригинала):
- `users` — баланс, XP, уровень, звание, is_admin, лимиты (bet_limits из bootstrap)
- `bets` — купоны: user, тип (single/express), сумма, кэф, статус, возможный выигрыш
- `bet_legs` — ноги экспресса: матч, рынок (код из оригинала: 1x2/dc/totals/btts/itb/ah), кэф, результат
- `odds_history` — движение кэфов (у оригинала эндпоинт есть, таблица наша)
- `achievements` / `user_achievements` — каталог достижений + прогресс (29 шт. у оригинала)
- `saved_coupons`, `favorites`, `notifications` — как в контракте оригинала
- `leaderboard` — не таблица, а VIEW по users.balance/season_points

## Принципы

0. **Турнир привязан к КОМАНДАМ (клубам), не к игрокам** (отличие от елобота, где
   игрок = сущность). Матчи, таблица, Elo, календарь — всё на клубах. Игрок лишь
   «сидит» в клубе и может быть заменён.
1. **Кошелёк живёт на игроке, не на клубе.** Монеты, XP, уровень, ставки, история
   (`users`, `bets`, `balance_history`) — привязаны к telegram_id и при заменах и
   трансферах НЕ двигаются и не обнуляются. Клубные сущности (Elo клуба, очки,
   состав) остаются у клуба. Замена игрока = обновить одну строку связи
   «игрок ↔ клуб», ничего больше не трогая — так замены не багают баланс.
2. **Туры — два режима на выбор (настройка сезона):** `challenge_place` (автоскан
   календаря/результатов с сайта) или `manual` (туры создаются админом в боте,
   как в елоботе: tour_number, календарь руками/жеребьёвкой). Режим можно
   переключать, уже внесённые данные не теряются.
3. **Админка выдаётся вручную:** root (`ADMIN_IDS` в env) раздаёт роли командой
   бота (назначить/снять турнирного админа, капитана). Никаких «самозванцев» по
   чат-правам. Всё в `tournament_admins` + audit log.
4. Секреты — только в env/`.env` (у елобота ключи утекли в репо — не повторять).
5. Вся ставка и баланс — в транзакции (`SELECT ... FOR UPDATE` как в Дракобете).
6. Один источник правды по кэфам: таблица markets/odds, фронт только читает.
7. Мини-апп фронт портируем с оригинала, но бэкенд пишем свой — контракт известен.
8. Каждый модуль можно включить/выключить флагом в `bot_settings` (key-value).
