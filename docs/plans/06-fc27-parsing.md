# ПАРСИНГ РЕЗУЛЬТАТОВ FC27 MOBILE (по примерам из `../samples/fc27-screens/`)

Примеры: 11 скринов в двух сериях (`photo_*_19-49-40.jpg`, `photo_*_19-49-50.jpg`) —
это эталоны для few-shot промпта и тестов. Оба варианта шапки встречаются в игре.

## Что видно на экране (тип «итоговая статистика матча»)

**Два варианта шапки:**
- Вариант А: карточки игроков слева/справа (ник + название лиги: «Логово фифарей»,
  «НЕТ ЛИГИ»), по центру логотип EA SPORTS FC MOBILE, счёт крупно «2 | 3», под ним таймер «90:00».
- Вариант Б: карточки игроков с эмблемами клубов и уровнем (65, 32), счёт в центре
  «3 - 1», таймер «90:00» под счётом.

**Счёт и время:**
- Обычный матч: таймер `90:00`.
- Овертайм: таймер `120:00`, рядом с каждым счётом в скобках — забитые пенальти:
  «(5) 3 (4)» = серия 5:4 (см. `photo_3_..._40.jpg`). Поле отдельное, НЕ в общий счёт.

**Таблица игроков (симметричная):**
- Колонки слева: ПОЗ | ИГРОКИ | ОБЩ | ИС | Г | А — команда-хозяин.
- Колонки справа зеркально: А | Г | ИС | ОБЩ | ИГРОКИ | ПОЗ — команда-гость.
- ПОЗ — позиция (ЦАЗ, ФРВ, ЦП, ПВ, ЛВ, ЛП, ЦОП, ВРТ…), ОБЩ — рейтинг карточки,
  ИС — «использовано», Г — голы, А — ассисты.
- 👑 рядом с именем = капитан.

## КРИТИЧЕСКИЙ нюанс: таблица прокручиваемая
На скрине видно только ~6-8 строк состава. В `photo_5_..._40.jpg` счёт 4:0, а видимых
голов только 1 — остальные забившие ниже видимой области. Игроки присылают 1–3 скрина
с прокруткой таблицы. Отсюда правила:
1. Счёт берём ТОЛЬКО из шапки (крупные цифры), никогда не сумму по таблице.
2. Голы/ассисты собираем со ВСЕХ присланных скринов, объединяя по имени игрока
   (дедуп: одно имя встречается на нескольких скринах — берём максимум, не сумму).
3. Валидация: сумма Г по таблице ≤ счёт из шапки; если меньше и скринов мало —
   пометить «не все бомбардиры видны» (или запросить ещё скрин, если включена опция).

## JSON-схема ответа ИИ (переработка промпта елобота)
```json
{
  "team_home": "Real Betis", "team_away": "Liverpool",
  "player_home": "temiyy", "player_away": "Rusli",
  "league_home": "Логово фифарей", "league_away": "НЕТ ЛИГИ",
  "score_home": 2, "score_away": 3,
  "timer": "90:00",
  "penalties": null | {"home": 5, "away": 4},
  "confidence": 0.0-1.0,
  "players": [
    {"side": "home|away", "name": "Antony", "pos": "ПВ",
     "goals": 2, "assists": 0, "captain": false}
  ],
  "warnings": ["видны не все строки таблицы", "сумма голов меньше счёта"]
}
```
Отличия от промпта елобота (FC Mobile старый): минут гола на этих скринах НЕТ
(только Г/А счётчики) — поле minute убираем; пенальти теперь в скобках у счёта,
а не отдельной серией; добавлены player/league из шапки и warnings.

## Правила сверки с БД
- `team_home/team_away` → нормализация имени → поиск клуба (у нас свои клубы, имена
  эмуляции FC могут не совпадать → маппинг клуб→команда эмуляции задаётся при
  назначении клуба, иначе фолбэк на player_home/player_away и сопоставление по юзерам).
- `player_*` → username в `players` (алиасы через player_aliases из елобота).
- Счёт → `matches.score1/score2`, пенальти → отдельные поля, голы → `match_goals`
  (только если опция бомбардиров включена создателем турнира).
- Дедуп скринов: sha256 → `processed_screenshots` (модуль елобота).

## Что берём из елобота
- Каскад провайдеров: OpenRouter free VL (7 моделей) → Groq → Gemini → NIM → OCR.space → tesseract.
- Кнопку «🔄 Другой моделью» при неуверенности (confidence < порога).
- Карточку подтверждения с кнопками ✅/❌ и формой ручной правки.

## Решение (2026-09-24): бомбардиры ВКЛЮЧЕНЫ
Голы по именам собираем из скринов (11 эталонов в `../samples/fc27-screens/` позволяют),
в настройке сезона у создателя — тумблер «собирать бомбардиров» (выкл → вносится
только счёт, голы руками). Правила дедупа и «сумма Г ≤ счёт» — выше.

## Тесты промпта (эталоны)
- По 3-4 скрина из каждой серии прогнать через промпт → сверить JSON глазами →
  зафиксировать ошибки → дополнить few-shot. Скрины с 120:00 и пенальти — обязательный кейс.
